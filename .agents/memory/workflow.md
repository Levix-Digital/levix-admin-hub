name: workflow
description: How work flows in this repository and the tool pitfalls already hit. Read before branching, committing, opening a pull request or releasing.
updated: 2026-11-14
---

- 2026-11-07: GitHub tools append a "Generated by" footer to pull request bodies, reviews and comments. Read each one back after posting and remove it by editing the pull request body; comments keep the footer, so report in the conversation instead of commenting.
- 2026-11-07: Final releases are published only by the owner's manual run of the promote workflow. The `release` environment has no required reviewers (not available on this plan); do not ask the owner to add one.
- 2026-11-14: Release candidates are cut by `candidate.yml` after a green `Tests` run on main, only when `docs/releases/vX.Y.Z-rc.md` exists (see `docs/releases/README.md`). Pushing tags from cloud sessions is refused by the git proxy.
- 2026-11-14: After an ADR, the technical specification or `.dev-cycle.json` changes, regenerate the constitution in the same pull request; gate 3 blocks a plan while it is stale.
